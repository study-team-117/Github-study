# GitHub-study

チーム開発に向けて、Git・GitHubの基本操作から応用までを学ぶための教材です。

## この教材について

本編では、コミットやブランチ操作、Pull Requestを使ったチーム開発を学びます。コンフリクトなどのトラブルへの対処や、GitHub Actions、rebaseなどの応用も扱います。

GitやGitHubを初めて使う人を対象に、実際にコマンドを実行しながら学べるようにまとめています。Windows・Macのどちらでも学習できるよう、OSごとに操作が異なる部分は各章で説明します。

## 事前準備

勉強会の前に、Gitのインストールと初期設定、GitHubへのログインと認証の準備を済ませ、PCで使うエディターを用意してください。

[事前準備資料：Git・GitHubのインストールと初期設定](docs/00-install.md)

## 学習の進め方

[事前準備](#事前準備)を済ませたら、本編の01章から進めます。

1. **01章：基本操作** — GitHubにリポジトリを作成し、ブラウザとPCの両方で変更を記録する。
2. **02〜03章：チーム開発** — PCでブランチを作成し、ブラウザでPull Requestを確認して変更を取り込む。
3. **04〜05章：トラブル対応と便利な操作** — エラーへの対処方法や日常的に役立つコマンドを学ぶ。
4. **06〜07章：機能紹介と応用** — GitHubの管理機能と、より高度なGit操作を学ぶ。
5. **08章：安全な開発** — 共有前の確認、漏えい時の初動、チームやAIツールに渡す権限を学ぶ。

| やりたいこと | 参照する教材 |

- **開発中**は、設計で迷ったときやエラーが出たときに該当箇所を読み、手元で試します。
- **開発終了後**は、選んだ方法と結果を教材の例と見比べ、次の開発で活かせることを振り返ります。

## 学習時の注意

- 最初は個人の練習用リポジトリで操作してください。
- チーム開発では、原則として作業ブランチからPull Requestを作成します。
- `git push --force` など履歴に影響する操作は、意味を理解せずに実行しないでください。
- パスワードやAPIキーなどの機密情報をコミットしないでください。

### 学習と開発でのAIの使い方

AIは学習や開発を支援する道具です。作業を任せる範囲は自分で決め、結果を採用するかどうかは人が判断します。

- **演習では**、まず教材を見ながら自分で考え、試したことと分からない点を整理します。行き詰まったら、AIにヒントや用語の説明を求めたり、エラーの原因候補を一緒に整理したりできます。自分の回答を書いた後の振り返りにも使えます。
- **実際の開発では**、調査・実装・テスト案・レビューなどにAIを活用できます。生成コードがどう動き、なぜその設計なのかを説明できるまで読み、AIの回答やレビューの指摘は仕様・公式資料・実行結果と照らし合わせます。

演習では、答えが合っているかに加え、選んだ操作や回答の理由を自分の言葉で説明できることを重視します。[AI支援開発の補足教材](docs/ai-development/README.md#学習時と開発時で任せる範囲を変える)
