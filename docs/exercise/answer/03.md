# 03 チーム開発の基本｜ミニ演習 回答例・解説

[← 演習に戻る](../03-team-exercise.md) ｜ [← 03章の本編](../../03-team.md) ｜ [目次に戻る](../../../README.md#目次)

以下は一例です。ブランチ名やファイル名は配布されたものに合わせ、コミットID・Issue番号は実際に表示された値を使います。

## 演習1：変更を取り込むPRを作る

**使用環境**　準備ではPCのエディターとターミナルを使います。演習のPR作成と確認はGitHubのブラウザで行います。

**選んだ理由**　PRでは `base` が取り込み先、`compare` が変更元です。向きが正しいことを確認すると、別のブランチへ変更を提案する事故を防げます。

GitHubで **Pull requests → New pull request** を開き、`base: main`、`compare: practice/usage` を指定します。READMEの差分を見てからPRを作り、たとえば次のように説明します。

**確認**　「READMEに教材の使い方を追加しました。差分で『使い方』の追記を確認しました。」PRが **Open** で、取り込み先が `main` であることを確認します。

## 演習2：同じPRでレビューの指摘に対応する

**使用環境**　ファイル編集とGit操作はPCのエディターとターミナルを使います。PRの確認・レビュー・マージはGitHubのブラウザで行います。

**選んだ理由**　同じ作業ブランチを更新すると、PRに新しい差分が加わり、どの指摘に対応したかを追えます。

レビュー担当は **Files changed** で「読む章の順番が分かるようにしてほしい」と伝えます。作成者は `practice/usage` で作業します。README に「事前準備資料で環境を整え、01章で基本操作を試す」と追記し、同じブランチから送ります。

```bash
git add README.md
git diff --staged
git commit -m "Explain the reading order"
git push -u origin practice/usage
```

**確認**　レビュー担当は同じPRで差分と返信を確認し、権限のある人がマージします。GitHubの `main` のREADMEを確認し、PCでも `git switch main` と `git pull --ff-only` で最新版を取り込みます。

## 演習3：取り込み先とPRの差分を見直す

**使用環境**　ファイルの変更はPCで作業し、PRとレビューはGitHubのブラウザを使います。差分の調査にはターミナルやエディターの比較表示を選べます。

**選んだ理由**　取り込み先と変更範囲は別の問題です。取り込み先を正しても依頼外の変更が残るため、元のブランチを保ったまま、必要な追加だけで新しいPRを作る方法を選べます。

最新の `main` から `practice/usage-only` を作り、使い方だけを元の差分からREADME末尾に移します。

```bash
git switch main
git pull --ff-only
git switch -c practice/usage-only
# README.md に使い方だけを追記
git add README.md
git diff --staged
git commit -m "Add usage instructions only"
git push -u origin practice/usage-only
```

**確認**　新しいPRの取り込み先が `main` で、目次が差分にないことをレビュー担当が確認します。元のPRには引き継ぎ先と理由を書き、不要になったPRを閉じます。同じPRを使う方針なら、取り込み先の変更だけでなく、不要な差分も解消する必要があります。
