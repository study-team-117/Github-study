# 03 チーム開発の基本｜ミニ演習 回答例・解説

[← 演習に戻る](../03-team-exercise.md) ｜ [← 03章の解説に戻る](../../03-team.md) ｜ [← 教材の目次に戻る](../../../README.md#目次)

02章でpushした `feature/branch-practice` を使う回答例です。03章の本編で変更を用意した場合は、ブランチ名を `docs/add-team-note`、ファイル名を `team-note.md` に読み替えてください。

## 課題1：Pull Requestを作る

GitHubの練習用リポジトリ `git-practice` を開き、**Pull requests → New pull request** を選びます。**base** に取り込み先の `main`、**compare** に変更元の `feature/branch-practice` を指定し、差分に `branch-practice.md` があることを確認します。

タイトルは「ブランチ演習のメモを追加」とします。説明欄の記入例は次のとおりです。

```markdown
## 変更内容
- ブランチを使う利点をまとめた branch-practice.md を追加しました。

## 確認方法
- GitHubで作業用ブランチを選び、メモが表示されることを確認しました。
```

**Create pull request** を押します。PR番号と **Open** が表示されたら作成できています。

## 課題2：差分を確認してマージする

1. **Files changed** で、`branch-practice.md` の追加内容を読み、今回の演習に関係するファイルだけが含まれていることを確認します。
2. 個人で練習する場合は、たとえば「差分はメモ1ファイルで、意図した見出しと本文が含まれていることを確認しました」とコメントします。ペアの場合は **Reviewers** から相手に依頼し、相手は **Review changes** から確認結果を送信します。
3. 修正が必要な場合は、下の発展課題と同じ手順で、開いているPRに変更を反映します。発展課題に取り組む場合も、ここで先に実施します。
4. 確認が終わったら **Merge pull request** など、利用できるマージ方法を選んで確定します。PRに **Merged** と表示され、GitHubのファイル一覧で `main` を選んだときにメモが開ければ完了です。

## 課題3：PCのmainを更新する

VSCodeのターミナルで `git status` を実行します。`nothing to commit, working tree clean` と表示されたら、次のコマンドを1行ずつ実行します。

```bash
git switch main
git pull --ff-only
```

`Fast-forward` と表示されれば、PCの `main` に更新が取り込まれています。すでに同じ変更を取り込んでいる場合は `Already up to date.` と表示されます。VSCodeでメモを開き、GitHub上の `main` と内容が一致することを確認します。

## 発展課題：同じPRに修正を反映する

PRが **Open** の間に取り組みます。PCの練習用リポジトリで `git status` を実行し、未コミットの変更がないことを確認してから、作業用ブランチに切り替えます。

```bash
git switch feature/branch-practice
```

VSCodeで `branch-practice.md` に「作業用ブランチに戻ると、追加したファイルが再び表示されました。」と追記して保存します。`git status` で対象を確認してからステージします。

```bash
git add branch-practice.md
git status
```

`Changes to be committed` にこのファイルだけが表示されていることを確認し、コミットしてpushします。

```bash
git commit -m "Clarify branch practice note"
git push
```

元のPRを再読み込みします。PR番号はそのままで、**Files changed** に追記した行が表示されます。確認後は課題2のマージに進みます。

### 考えてみようの回答例

| 操作 | 更新する場所 |
|---|---|
| 作業用ブランチで `git push` | GitHub上の作業用ブランチ。開いているPRの差分も更新される。 |
| GitHub上でPRをマージする | GitHub上の `main`。 |
| PCで `main` に切り替えて `git pull` する | PCの `main` と作業フォルダ。 |
