## 基本演習

### 課題1：PC用の設定と共有用の見本を作る

3ファイルを保存してから `git status --short --ignored` を実行します。次のように表示されます。

```text
?? .env.example
?? .gitignore
!! .env
```

`??` は未追跡、`!!` は無視対象です。`.env` だけが無視対象になっています。

## 応用演習

### 課題2：コミット予定の差分を確認する

```bash
git add .env.example .gitignore
git diff --cached
```

`.env.example` の追加行に `DEMO_API_KEY=replace-me`、`.gitignore` の追加行に `.env` が表示されます。`diff --git` で始まる差分がこの2ファイル分だけであることを確認します。

```bash
git commit -m "Add example configuration"
git show --stat HEAD
```

`git show --stat HEAD` のファイル一覧が2件で、VSCodeのエクスプローラーには `.env` も残っていれば完了です。

## 発展演習

### 公開後の対応を考える

キーを管理する担当者が、発行元の管理画面でキーを失効します。担当者が自分でない場合は、失効を依頼し、完了を確認します。チームへの連絡は次のように書けます。

> 練習用リポジトリでAPIキーの誤共有が判明しました。対象は設定ファイルと該当コミットです。キーの失効状況を確認し、利用履歴とリポジトリ履歴への対応を相談したいです。

実際に対応するときは、管理者にファイルパス、コミットID、判明時刻を伝えます。削除PRは新しいコミットを追加するため、過去のコミットからは値を読める状態が残ります。発行元での失効を先に行い、履歴の対応は管理者と進めます。
