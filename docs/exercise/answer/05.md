# 05 便利なGitコマンド・小技｜ミニ演習 回答例・解説

[← 演習に戻る](../05-tips-exercise.md) ｜ [← 05章の本編](../../05-tips.md) ｜ [目次に戻る](../../../README.md#目次)

以下は一例です。ブランチ名やファイル名は配布されたものに合わせ、コミットID・Issue番号は実際に表示された値を使います。

## 演習1：同じファイルから必要な差分だけを記録する

**使用環境**　PCのエディターとターミナルを使います。差分と履歴はターミナルで確認します。

**選んだ理由**　ファイル全体を選ぶと案内とメモの両方がコミット対象に入ります。差分のまとまりごとに選べば、案内だけを記録できます。

```bash
git diff -- README.md
git add -p -- README.md
git diff --staged -- README.md
git commit -m "Clarify the guide"
git show HEAD -- README.md
git diff -- README.md
```

`git add -p` では案内のまとまりで `y`、メモのまとまりで `n` を選びます。2か所が一緒に表示された場合は、分割できるときに `s` を選び、表示された内容を再確認します。コミット前に、ステージ済みの差分が案内だけになっていることを確かめます。

**確認**　最新のコミットの差分には案内の追記だけがあり、未ステージの差分には書きかけのメモが残ります。

## 演習2：急ぎの修正を分けて作業を再開する

**使用環境**　PCのエディターとターミナルを使います。作業の分離と再開に使うGit操作はターミナルで行います。

**選んだ理由**　同じファイルを別の作業でも編集するため、書きかけのガイドを一時退避してから急ぎの変更を分けると、両方が混ざりません。

`practice/guide` 上で退避し、`main` を土台に修正ブランチを作ります。

```bash
git stash push -m "WIP guide"
git switch -c fix/readme-wording main
# README.md の「共用」だけを「共有」に修正
git diff
git add README.md
git commit -m "Fix wording in README"
git switch practice/guide
git stash pop
```

**確認**　`git show fix/readme-wording` で誤記だけが直り、`git diff -- README.md` でガイドが戻っていれば完了です。

## 演習3：退避した作業から必要な1件を復元する

**使用環境**　PCで作業します。退避内容と復元結果を説明できる方法なら、ターミナルとエディターの差分表示を組み合わせて構いません。準備欄のコマンドを実行する場合はBashを使います。

**選んだ理由**　退避名だけでは目的の変更を判断できないので、内容を比較します。適用と退避の削除を分けると、復元結果を確認するまで元の記録を保てます。

`git stash list` で2件を見つけ、それぞれの差分を読みます。次の例では必要な記録が `stash@{1}` だったとします。実際に表示される番号を使います。

```bash
git stash show -p 'stash@{0}'
git stash show -p 'stash@{1}'
git switch practice/resume
git stash apply 'stash@{1}'
git diff -- guide.md
git stash list
```

**確認**　`guide.md` に修正済みの見出しと「レビュー待ちの確認方法」の追記があり、不要な追記がないことを確認します。もう1件が退避一覧に残っていれば完了です。適用した記録も、確認が済むまで残して構いません。
