## 基本演習

### 課題1：Issueに作業と完了条件を書く

タイトルは「GitHub機能の学習メモを追加」です。本文の例です。

```markdown
## 作業内容
IssuesとPull Requestの用途を学習メモにまとめる。

## 完了条件
- github-features-note.md に2つの機能の用途が書かれている。
- GitHub上の main からメモを読める。
```

作成したIssueのタイトル付近に表示される番号を控えます。

## 応用演習

### 課題2：Pull RequestをIssueに関連付ける

未コミットの変更がないことを確認してから、次のコマンドを1行ずつ実行します。pullに失敗した場合はそこで止め、原因を確認します。

```bash
git switch main
git pull --ff-only
git switch -c docs/github-features-note
```

`github-features-note.md` の記入例です。

```markdown
# GitHub機能の学習メモ

- Issues：作業内容と完了条件を記録する。
- Pull Request：変更を提案し、差分を確認してから取り込む。
```

保存後、`git status` で対象を確認してから記録します。

```bash
git add github-features-note.md
git status
git commit -m "Add GitHub features note"
git push -u origin docs/github-features-note
```

PRの **base** を `main`、**compare** を `docs/github-features-note` にします。説明欄の例です。番号は自分のIssueに置き換えてください。

```markdown
## 変更内容
IssuesとPull Requestの用途を説明するメモを追加しました。

## 確認方法
Files changedで、メモに2つの機能の説明があることを確認しました。

Closes #12
```

マージ後はIssueを開き、**Closed** とPRへの参照を確認します。Issueが開いたままなら、番号が合っているか、既定ブランチ向けのPRがマージされたかを確認します。

## 発展演習

### Actionsの失敗ログから原因を見つける

`main` を更新して `practice/actions-check` を作り、[本編のPythonとYAMLの例](../../06-features.md#pythonの最小例)を保存します。最初のテストは `assert add(2, 3) == 6` にします。

```bash
git add test_sample.py .github/workflows/python-test.yml
git status
git commit -m "Add Python check practice"
git push -u origin practice/actions-check
```

`main` 向けのPRを開きます。最新のチェックで `Run tests` が失敗し、ログに `assert 5 == 6` のように表示されます。足し算の結果は `5` なので、テストの期待値を `5` に直します。

```bash
git add test_sample.py
git commit -m "Fix expected test result"
git push
```

同じPRの最新コミットに対応するチェックを開き、`Run tests` が成功し、ログに `1 passed` と表示されることを確認します。実行自体が表示されない場合は、ファイルの場所、PRの対象ブランチ、リポジトリのActions設定を確認します。
