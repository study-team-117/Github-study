## 課題1：ローカルの変更をGitHubへ反映

### ① `profile.md` を作成する

VSCodeで `git-practice` フォルダを開き、新しいファイル `profile.md` を作成します。記入例：

```markdown
# 自己紹介

## 名前
Git学習者

## 興味のある技術
- Python
- AI

## 勉強会で学びたいこと
GitHubを使ってチーム開発ができるようになりたいです。
```

※ 公開リポジトリには本名や個人情報を書く必要はありません。

### ② 変更を確認する

VSCodeのターミナルで、**`git-practice` フォルダ内**にいることを確認して実行します。

```bash
git status
```

`Untracked files:` の下に `profile.md` が表示されれば、Gitが新しいファイルを検出しています。続けて、ほかに変更が表示されていないことを確認します。

### ③ `profile.md` だけをステージングする

```bash
git add .
git status
```

`Changes to be committed:` の下に `new file: profile.md` が表示されることを確認します。

`git add .` は今いるフォルダ以下の変更をまとめてステージします。ほかの未ステージの変更がある場合は、`git add profile.md` で対象を指定できます。コミットの前に `git status` を見て、`Changes to be committed` に `profile.md` だけがあることを確認します。

### ④ コミットする

```bash
git commit -m "Add profile"
```

コミットは**自分のPC上のGit履歴に変更を記録する操作**です。この時点ではGitHubにはまだ反映されません。

### ⑤ GitHubにpushする

```bash
git push
```

01章でクローンした練習用リポジトリでは、Gitが送信先を覚えているため `git push` だけで送れます。認証画面が出た場合は案内に従ってログインします。

GitHubの `git-practice` リポジトリを開き、`profile.md` が表示されていれば成功です。コミット履歴にも `Add profile` が残ります。

## 課題2：GitHub上の変更をPCへ取り込む

### ① ブラウザでREADMEを編集する

1. GitHubの `git-practice` リポジトリを開きます。
2. `README.md` を選び、編集ボタン（鉛筆アイコンなど）を押します。
3. ファイル末尾に次を追加します。

```markdown
## 学習メモ

ブラウザからREADMEを編集しました。
```

4. `Commit changes` を押して、`main` ブランチに変更をコミットします。

### ② PC側で最新の変更を取り込む

ローカルのファイルは追加編集せず、ターミナルで次を実行します。

```bash
git status
git pull
```

`git status` で未コミットの変更がないことを確認してからpullします。`git pull` はリモートの変更を取得し、現在のブランチに取り込みます。

### ③ 反映を確認する

VSCodeでローカルの `README.md` を開き、`## 学習メモ` が追加されていれば成功です。

```bash
git status
```

`nothing to commit, working tree clean` と表示されれば、作業ツリーに未コミットの変更はありません。ただし、これだけでリモートとの完全な一致を保証するわけではありません。

## 発展課題：差分と履歴を確認する

### ① `profile.md` を追加編集する

「興味のある技術」に、例えば `- Web開発` を1行追加します。

### ② 差分を確認する

```bash
git diff -- profile.md
```

追加した行が `+` で表示されます。`git diff` は、原則として**まだステージングしていない変更**を確認するコマンドです。

### ③ 変更をコミットしてpushする

```bash
git add profile.md
git commit -m "Update interests"
git push
```

### ④ 履歴を確認する

```bash
git log --oneline -5
```

例（先頭の英数字は環境ごとに異なります）：

```text
abc1234 Update interests
fed4321 ブラウザからREADMEを更新
def5678 Add profile
...
```

GitHubのブラウザで作ったREADMEのコミットも、pull後の履歴に含まれているはずです。

### 考えてみよう：回答例

| 質問 | 回答例 |
|---|---|
| `commit` と `push` の違いは？ | `commit` はローカルに履歴を記録し、`push` はそのコミットをGitHubなどのリモートに送信する。 |
| `pull` はいつ必要？ | GitHub上や他のPCで進んだ変更を、自分のローカルブランチに取り込みたいとき。 |
| `git status` は何のため？ | 変更されたファイル、ステージング状態、ブランチの状態などを確認するため。 |
| `git add profile.md` を使う理由は？ | コミットに含めたいファイルだけを指定できるため。 |

## よくあるつまずき

| 状況・メッセージ | 確認すること |
|---|---|
| `fatal: not a git repository` | ターミナルでcloneしたリポジトリのフォルダに移動しているか。 |
| `Author identity unknown` | `git config --global user.name` と `user.email` の設定。 |
| `nothing to commit` | ファイルを保存したか、すでにコミット済みではないか。 |
| `Permission denied (publickey)` | SSH方式を使っている場合、GitHubへの公開鍵登録・鍵の読み込み。 |
| `rejected (non-fast-forward)` | リモート側に未取得のコミットがないか。無理に `--force` しない。 |
| `git pull` で競合が発生 | 同じ箇所に異なる変更がないか。競合解消は後の章で扱う。 |
