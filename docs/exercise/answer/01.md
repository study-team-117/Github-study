# 01 基本操作｜ミニ演習 回答例・解説

[← 演習に戻る](../01-basic-exercise.md) ｜ [← 01章の本編](../../01-basic.md) ｜ [目次に戻る](../../../README.md#目次)

以下は一例です。ブランチ名やファイル名は配布されたものに合わせ、コミットID・Issue番号は実際に表示された値を使います。

## 演習1：ブラウザ編：GitHubで編集し、コミット履歴を確認する

**使用環境**　ブラウザだけを使います。PCへのクローンやターミナル操作は不要です。

**選んだ理由**　ブラウザから直接コミットすると、変更がGitHubの履歴に記録されます。ファイルの表示とコミットの差分を見比べると、どの行がどの記録で追加されたかを確認できます。

1. GitHubで `main` の `README.md` を開き、鉛筆アイコンから編集します。「## 学習メモ」の下に、たとえば「変更を履歴に残す操作を試します。」と書きます。
2. **Commit changes** で「学習メモを追加」などのメッセージを入力し、個人練習用の `main` に直接コミットします。
3. `README.md` を開き直し、**History** から今回のコミットを開きます。

**確認**　`main` のREADMEに学習メモがあり、開いたコミットの差分に見出しと文章が追加行として表示されます。

## 演習2：ローカル編：PCの変更をGitHubに反映する

**使用環境**　PC上のエディターでファイルを編集し、変更の記録と送信はターミナルのGitコマンドで行います。ブラウザはGitHubで結果を確認するために使います。

**選んだ理由**　PC上の保存とGitHubへの反映には、それぞれ別の操作が必要です。共有するファイルを指定して履歴に記録すると、別の変更が混ざりにくくなります。

PC上のエディターで `README.md` に「## 自己紹介」を追加し、ニックネームと興味のある技術を書いて保存します。練習用リポジトリのターミナルで、`main` にいることと対象ファイルを確認してから次を実行します。

```bash
git status
git add README.md
git diff --staged
git commit -m "Add self introduction"
git push origin main
```

**確認**　GitHubのブラウザで `README.md` と履歴を開きます。PCで作ったコミットがあり、変更ファイルが `README.md` だけで、自己紹介が表示されれば完了です。

## 演習3：共有する変更を選ぶ

**使用環境**　PC上のエディターとターミナルを使います。ブラウザではGitHub上のファイルと履歴を確認します。

**選んだ理由**　未記録のメモと、共有したい変更を分けて扱います。共有対象だけをステージすると、メモを消さずにコミットから外せます。

次を実行し、ステージ済みの差分が紹介文だけであることを読んでからコミットします。

```bash
git status
git add profile.md
git diff --staged
git commit -m "Revise published profile"
git push origin main
git status --short
```

**確認**　GitHubの最新コミットに `notes.md` は含まれず、手元の `git status --short` には ` M notes.md` が残ります。

## 演習4：PCとGitHubの変更を両方残す

**使用環境**　PC上のエディターとターミナル、GitHubを開くブラウザを使います。ブラウザでのファイル編集は準備で行い、演習ではPC側の変更とGitHub側の既存の更新を扱います。

**選んだ理由**　案内の更新はGitHub側の履歴にあり、紹介文とメモはPC側だけにあります。紹介文だけを記録し、メモを一時退避すれば、共有されていないコミットだけをGitHubの最新履歴の上に移せます。競合しない状態を配布するので、案内を上書きする必要もありません。

まず `git status --short` と `git fetch origin` の後の `git log --oneline HEAD..origin/main` で状態を調べます。続けて次を実行します。

```bash
git add profile.md
git diff --staged
git commit -m "Update profile"
git stash push -m "Keep unfinished notes" -- notes.md
git pull --rebase origin main
git push origin main
git stash pop
```

**確認**　案内と紹介文をGitHubで開き、メモは手元の `git diff -- notes.md` で確認します。pushで案内の更新を上書きしたり、メモを含めたりする必要はありません。
