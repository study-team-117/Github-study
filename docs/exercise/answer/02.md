# 02 ブランチの操作｜ミニ演習 回答例・解説

[← 演習に戻る](../02-branch-exercise.md) ｜ [← 02章の本編](../../02-branch.md) ｜ [目次に戻る](../../../README.md#目次)

以下は一例です。ブランチ名やファイル名は配布されたものに合わせ、コミットID・Issue番号は実際に表示された値を使います。

## 基本演習

### 作業用ブランチに変更を記録する

**選んだ理由**　変更を作業用ブランチで記録すると、`main` の履歴を動かさずに作業できます。

`main` から次を実行し、切り替えたあとで `outline.md` を作ります。

```bash
git switch -c practice/outline
# outline.md に「学習の流れ」と書いて保存
git add outline.md
git commit -m "Add learning outline"
git log -1 --oneline
git diff --name-only main..practice/outline
```

**確認**　差分に `outline.md` が表示されます。`git log -1 --oneline main` で演習前に控えたコミットが変わっていないことを確かめます。

## 応用演習

### 未記録の下書きを別ブランチで共有する

**選んだ理由**　下書きは未記録なので、作業先を切り替えてから記録できます。GitHubには作業用ブランチだけを送れば、他の人が下書きを確認できます。

`main` にいることと `draft.md` が未追跡であることを確かめてから実行します。

```bash
git status --short
git switch -c practice/share-draft
git add draft.md
git commit -m "Add review draft"
git push -u origin practice/share-draft
```

**確認**　GitHubのブランチ選択で `practice/share-draft` に下書きがあることと、`main` にないことを確認します。手元でも `git log -1 --oneline main` が作業前と同じか確認します。

## 発展演習

### 最新の案内と共有したいガイドだけをそろえる

**選んだ理由**　確認用ブランチの土台は最新の `main` です。下書きブランチを丸ごと統合するとメモも入るため、ガイドだけを指定して取得します。

`main` が最新で作業フォルダがきれいなことを確認して進めます。`--source` で取得元を指定できます。

```bash
git switch main
git switch -c practice/preview
git restore --source=practice/draft --staged --worktree -- guide.md
git diff --staged --name-status
git commit -m "Copy guide for review"
git diff --name-only main..practice/preview
git show practice/draft:notes.md
```

**確認**　確認用ブランチで最新の案内と `guide.md` を開けて、`main` との差分がガイドだけなら完了です。ブランチを移動してファイルをコピーする方法でも、同じ確認を行えます。
