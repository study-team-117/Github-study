# 02 ブランチの操作｜ミニ演習 回答例・解説

[← 演習に戻る](../02-branch-exercise.md) ｜ [← 02章の本編](../../02-branch.md) ｜ [目次に戻る](../../../README.md#目次)

01章で使った自分の `git-practice` をVSCodeで開き、ターミナルで `git status` を実行します。`nothing to commit, working tree clean` と表示されたら始めます。

## 基本演習

### 課題1：作業用ブランチでコミットする

```bash
git switch main
git switch -c feature/branch-practice
git branch
```

`git branch` の出力で `* feature/branch-practice` と表示されれば、新しいブランチに切り替わっています。

VSCodeで `branch-practice.md` を作成して保存します。記入例は次のとおりです。

```markdown
# ブランチ演習

作業用ブランチを使うと、mainを保ったまま変更を試せます。
```

`git status` の `Untracked files` に `branch-practice.md` だけが表示されていることを確認します。

```bash
git add .
git status
```

`Changes to be committed` に `new file: branch-practice.md` だけが表示されたらコミットします。

```bash
git commit -m "Add branch practice"
```

## 応用演習

### 課題2：ブランチを切り替えてファイルを確認する

```bash
git switch main
```

VSCodeのファイル一覧から `branch-practice.md` が消えます。次のコマンドで作業用ブランチに戻ると、同じファイルが再び表示されます。

```bash
git switch feature/branch-practice
```

ブランチを切り替えると、そのブランチの内容が作業フォルダに表示されます。

### 課題3：作業用ブランチをGitHubに送る

```bash
git push -u origin feature/branch-practice
```

GitHubの練習用リポジトリで、ブランチ選択メニューから `feature/branch-practice` を選ぶと `branch-practice.md` が表示されます。`main` を選ぶと表示されません。

**考えてみようの回答例**　pushで更新したのはGitHub上の `feature/branch-practice` です。`main` へ変更を取り込むには、03章で学ぶPull Requestのマージなどを行います。

## 発展演習

### 2回目の変更を送り、ブランチを比較する

`git status` で作業用ブランチにいることと作業フォルダがきれいなことを確認し、`branch-practice.md` に1行追記して保存します。たとえば「mainに切り替えると、作業用ブランチで追加したファイルは一覧から消えました。」と書けます。

```bash
git diff
git status
```

`git diff` の `+` で始まる行に追記が表示されます。`git status` で変更が今回のファイルだけなら、ステージします。

```bash
git add .
git status
```

`Changes to be committed` に今回のファイルだけがあることを確認してから、コミットしてpushします。

```bash
git commit -m "Update branch practice"
git push
```

最初のpushで `-u` を付けて接続先を設定したため、今回は `git push` だけで送れます。GitHubで作業用ブランチを開き、追記が反映されていることを確認します。

#### 差分と履歴を確認する

```bash
git diff --stat main..feature/branch-practice
git log --oneline main..feature/branch-practice
```

- `git diff --stat` は両ブランチの最新コミットの**ファイル内容**を比較します。この演習で差分に出るファイルは `branch-practice.md` の1つです。
- `git log --oneline` は作業用ブランチからたどれて `main` からはたどれない**コミット**を表示します。上から `Update branch practice`、`Add branch practice` の順です。左に表示される短いコミットIDは環境によって異なります。

**考えてみようの回答例**　同じファイルを追加してから編集したため、変わったファイルは1つ、変更を記録したコミットは2つです。
