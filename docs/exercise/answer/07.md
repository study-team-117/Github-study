# 07 Git・GitHub応用編｜ミニ演習 回答例・解説

[← 演習に戻る](../07-advanced-exercise.md) ｜ [← 07章の本編](../../07-advanced.md) ｜ [目次に戻る](../../../README.md#目次)

以下は一例です。ブランチ名やファイル名は配布されたものに合わせ、コミットID・Issue番号は実際に表示された値を使います。

## 演習1：共有前の作業ブランチの土台を更新する

**使用環境**　PCのターミナルでGitの履歴を操作・確認します。GitHubへの接続は不要です。

**選んだ理由**　未共有の作業用ブランチなら、作業コミットを最新の `main` の後ろに並べ直せます。`main` 自体は動かす必要がありません。

作業前の `main` のコミットIDを控え、作業用ブランチを更新します。

```bash
git rev-parse main
git switch practice/guide
git rebase main
git log --oneline --graph --all
git diff --name-only main..practice/guide
git rev-parse main
```

**確認**　履歴で `main` の直後にガイドの変更があり、`guide.md` が読めます。前後で `main` のIDは同じです。

## 演習2：別ブランチから公開対象の変更だけを取り込む

**使用環境**　PCのターミナルで履歴を調べ、選んだコミットを扱います。GitHubへの接続は不要です。

**選んだ理由**　ブランチ全体を統合するとメモも入ります。公開用の1件を選べば、取り込み元を変更せずに必要な変更だけを記録できます。

`git log --oneline main..practice/draft` でガイドを追加したIDを探し、`git show` で変更対象を確認します。以下の `GUIDE_COMMIT_ID` は実際のIDに置き換えます。

```bash
git switch practice/release
git cherry-pick GUIDE_COMMIT_ID
git diff --name-only main..practice/release
git ls-tree --name-only practice/draft
```

`git ls-tree --name-only` は指定したコミットのファイルやフォルダの名前だけを表示します。省くと種類やオブジェクトIDなども表示されるため、取り込み元に残っているファイル名を確かめるときは `--name-only` を使います。

**確認**　公開側の差分は `guide.md` のみです。取り込み元のファイル一覧には `guide.md` と `memo.md` が残ります。取り込み元の `git show GUIDE_COMMIT_ID` と取り込み先の `git show HEAD` を見比べ、ガイドを追加する変更が取り込まれたことを説明します。

## 演習3：不具合が入った記録を特定し、後続の変更を保つ

**使用環境**　GitHubには接続せず、PCで調査・検証します。判定結果とコミットを示せれば、エディターの履歴表示や自動判定も利用できます。準備欄のコマンドを実行する場合はBashを使います。

**選んだ理由**　同じ判定で正常と失敗を繰り返し調べると、コミット名から推測するより確実に原因を特定できます。原因が1件で、後続変更が別ファイルなら、その1件の効果を打ち消せます。

最新で失敗することと、`practice-good` で正常なことを確かめます。調査中は `display.txt` の内容を見て、`status=ready` があれば `git bisect good`、それ以外なら `git bisect bad` と判定します。

```bash
git bisect start
git bisect bad
git bisect good practice-good
# Git が選ぶ履歴ごとに display.txt を読み、正常・失敗を記録
# 最初の失敗コミットのIDを控える
git bisect reset
```

**確認**　原因コミットとその直前を `git show FAILING_ID:display.txt` と `git show FAILING_ID^:display.txt` で比較します。IDを実際の値に置き換え、`git switch -c fix/display` のあと `git revert --no-edit FAILING_ID` を実行します。修正後の表示と `lesson.md`、`faq.md`、`glossary.md` が残っていることを確認します。
