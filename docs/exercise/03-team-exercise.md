# 03 チーム開発の基本｜ミニ演習

> **演習の目安**　基本 5〜8分・個人｜応用 10〜15分・ペア｜発展 20〜25分・ペア
>
> 事前準備を終えてからの目安です。本編は演習中も参照できます。発展は時間内の完答を前提としません。

## 事前準備

GitとVSCodeの準備を済ませ、担当者から配布された初期状態を開きます。各演習の初期状態は個別に用意します。ペアの場合は、作業担当と確認担当を先に決めます。

教室で用意した練習専用の環境を使います。実際のプロジェクトや教材本体で作業したり、共有済みの履歴を書き換えたりしないでください。

[講師向けの準備](instructor-setup.md#03章の準備)

## 基本演習

### 変更を取り込むPRを作る

**初期状態**　共有済みの `practice/usage` は `main` から分かれ、READMEに使い方を追記しています。まだPRはありません。

**課題**　使い方の追加を `main` に提案してください。

**達成条件**　取り込み先が `main` のPRがある。変更の目的と、使い方を確認した方法が書かれている。

## 応用演習

### 同じPRでレビューの指摘に対応する

**初期状態**　READMEに「教材を読む」という使い方を追記したPRが開いています。初めて読む人には、どの順で読むかが分かりません。

**課題**　作成者とレビュー担当に分かれ、初めて読む人が次に何をすべきか分かるように改善してください。

**達成条件**　指摘・修正・再確認が同じPRに残っている。マージ後の `main` に読む順番があり、手元で最新版も確認できる。

## 発展演習

### 取り込み先とPRの差分を見直す

**初期状態**　依頼は「README末尾に使い方を追記する」です。開いているPRは `practice/review-base` 向けで、使い方だけでなく、依頼にない目次変更も含みます。

**課題**　ペアで取り込み先と変更範囲を検討してください。既存の `main` と共有済みブランチの履歴を保ち、レビュー可能な状態まで整えます。

**達成条件**　`main` 向けのPRの差分に使い方の追記だけがある。元のPRを修正したか出し直したか、その理由と再確認の結果が残っている。
