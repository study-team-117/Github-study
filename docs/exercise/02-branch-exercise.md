# 02 ブランチの操作｜ミニ演習

[← 02章の本編](../02-branch.md) ｜ [目次に戻る](../../README.md#目次)

> **演習の目安**　基本 5〜7分・個人｜応用 8〜12分・個人｜発展 15〜20分・個人
>
> 所要時間は問題に取り組む時間の目安です。授業ではまず各課題の「準備」を一緒に行います。本編は演習中も参照できます。発展は時間内の完答を前提としません。

## 事前準備

[GitとVSCodeの初期設定](../00-install.md)を済ませ、下の手順を使ってその場で練習環境を作ります。前の演習の状態を使う場合は、各課題の準備欄に記載しています。

課題ごとにREADMEだけを記録した `main` から始めます。基本・発展は、新規の空フォルダで `git init -b main` を実行し、READMEを最初のコミットに記録すれば準備できます。応用はGitHubでREADME付きの練習リポジトリを作り、PCにクローンします。

実際のプロジェクトや教材本体で作業したり、共有済みの履歴を書き換えたりしないでください。

## 基本演習

### 作業用ブランチに変更を記録する

#### 準備

VSCodeで練習用フォルダを開きます。現在のブランチが `main` で、README以外の変更がなければ準備完了です。比較用に、現在の `main` のコミットIDを控えます。

#### ここから演習

**初期状態**　練習リポジトリの `main` は更新済みで、未記録の変更はありません。

**課題**　`practice/outline` を作業先として用意し、`outline.md` に「学習の流れ」と1行書いて、そのブランチの変更履歴に残してください。

**達成条件**　作業用ブランチにファイルと履歴がある。`main` の内容と履歴は演習前と同じ。

## 応用演習

### 未記録の下書きを別ブランチで共有する

#### 準備

1. 練習リポジトリをクローンしたフォルダを、VSCodeで開きます。
2. `main` のまま `draft.md` を作り、「# 下書き」と書いて保存します。履歴には追加しません。
3. GitHub側にも下書きがないことを確認し、手元とGitHubの `main` の開始時のコミットIDを控えます。

#### ここから演習

**初期状態**　`main` を開いたまま、まだ履歴に記録していない `draft.md` を作ってしまいました。GitHubにも下書きはありません。

**課題**　チームが下書きを読める作業用ブランチをGitHubに用意してください。PCとGitHubの `main` は元の状態を保ちます。

**達成条件**　GitHubの作業用ブランチで下書きを読める。PCとGitHubの `main` は演習前と同じコミットを指している。

## 発展演習

### 最新の案内と共有したいガイドだけをそろえる

#### 準備

1. READMEだけを記録した `main` で、`git switch -c practice/draft` を実行します。
2. `guide.md` に「# 学習ガイド」、`notes.md` に「# 未承認メモ」と書き、両方を下書きブランチにコミットします。
3. `git switch main` で戻り、READMEに「集合は15時」と追記してコミットします。準備はここで止め、両ブランチを残します。

#### ここから演習

**初期状態**　古い `main` から分けた `practice/draft` に、共有したい `guide.md` と未承認の `notes.md` が記録されています。その後 `main` では `README.md` の案内が更新されました。

**課題**　最新の案内とガイドを含む `practice/preview` を用意してください。`main` と元の下書きブランチを変更せず、未承認のメモは下書きブランチに残します。

**達成条件**　`practice/preview` は最新の `main` を含み、比較した差分は `guide.md` だけ。元のブランチではメモも読める。
