## 事前準備

[事前準備資料](../00-install.md)に沿ってGitの初期設定を済ませ、下の手順で練習環境を作ります。前の演習の状態を使う場合は、各課題の準備欄に記載しています。

ファイル編集はPC上のエディターで行います。VSCodeを推奨しますが、使い慣れたエディターでも構いません。Gitコマンドを練習する課題ではターミナルを使い、PR・レビュー・Issues・ActionsなどのGitHubの機能はブラウザで操作します。

基本・応用は、課題ごとに空のフォルダを用意して `git init -b main` で開始します。発展はペア用のGitHub練習リポジトリを作り、相手を共同作業者に招待してからクローンします。

実際のプロジェクトや教材本体で作業したり、共有済みの履歴を書き換えたりしないでください。

## 基本演習

### 編集を残したままコミット対象から外す

**使用環境**　PCのターミナルでGitの状態を確認・操作し、編集内容はエディターで確認します。GitHubへの接続は不要です。

#### 準備

1. `practice.md` に「# 練習メモ」と書いて、最初のコミットに記録します。
2. 同じファイルに「あとで使う追記。」を追記して保存します。
3. `git add practice.md` で追記をコミット対象にしたところで止めます。コミットはまだ作りません。

#### ここから演習

**初期状態**　`practice.md` の追記がコミット予定に含まれています。まだ履歴には入っていません。

**課題**　追記を後で使えるように残し、今回のコミット対象から外してください。

**達成条件**　コミット対象に追記がなく、ファイルを開くと追記を読める。

## 応用演習

### 両方の意図が残るように競合を解消する

**使用環境**　PCのターミナルで統合の状態を管理します。競合箇所の編集には、使い慣れたエディターやその競合解消画面を使えます。

#### 準備

1. READMEの先頭行を「確認方法：まず手順を読む」としてコミットします。
2. その時点から `practice/conflict` を作り、READMEの先頭行を「確認方法：VSCodeで差分を見る」に変更します。`branch-note.md` に「作業ブランチのメモ」と書き、2ファイルをコミットします。
3. `main` に戻り、READMEの先頭行を「確認方法：ターミナルで状態を見る」に変更してコミットします。2つのブランチを用意したところで止めます。

#### ここから演習

**初期状態**　`main` と `practice/conflict` で、READMEの同じ案内行が別々に更新されています。作業用ブランチには別ファイルの追加もあります。

**課題**　2つの案内を1行にまとめて `main` に統合してください。案内以外の変更も保ちます。

**達成条件**　両方の案内が読めて、競合の印がない。作業用ブランチで追加した別ファイルも残り、統合が完了している。

## 発展演習

### 誤変更を取り消し、取り込み待ちのPRを整える

**使用環境**　変更とGit操作はPCで行い、PRとレビューにはGitHubのブラウザを使います。競合の内容を説明できれば、エディターの競合解消画面も利用できます。

#### 準備

1. `main` に `deadline.md` の「締切：6月10日」と、READMEの「質問は担当者まで。」をコミットして共有します。
2. この時点から `practice/announcements` を作り、READMEを「質問は掲示板へ。」に変更してコミットします。作業ブランチを共有し、`main` 向けのPRを開きます。
3. `main` で次の3件を順に別々のコミットとして記録して共有します。`deadline.md` を「締切：6月1日」に変える、`contacts.md` に「連絡先：案内担当」を追加する、READMEの同じ行を「質問は担当者へ。急ぎの場合は直接連絡してください。」に変える、の3件です。PCで編集し、ターミナルで記録・共有します。
4. PRに競合が表示されることと、ペアの相手が練習リポジトリを開けることを確認します。締切の訂正と競合解消はまだ行いません。

#### ここから演習

**初期状態**　共有済みの `main` には `deadline.md` の誤った締切変更と、その後に追加された `contacts.md` があります。別件のPRでは、READMEの案内行が `main` と競合しています。

**課題**　正しい締切の6月10日に戻したうえで、PRを取り込めるようにしてください。共有済みの履歴と連絡先を保ち、締切の訂正と競合への対応が区別できる形で残します。

**達成条件**　`main` に正しい締切と連絡先がある。PRの競合が解消され、READMEに両者の意図が残る。相手がその状態を確認し、2つの問題への判断を説明できる。
