# 08 セキュリティと安全な開発｜ミニ演習

> **演習の目安**　基本5分 ｜ 応用5分 ｜ 発展5〜10分
>
> 事前準備を終えてからの目安です。形式は個人で、発展は任意です。

## 事前準備

既存のリポジトリの外に空のフォルダ `git-security-practice` を作り、VSCodeで開きます。ターミナルで `git init -b main` を実行します。演習ではダミー値だけを使い、GitHubへのpushは不要です。

## 基本演習

### 課題1：PC用の設定と共有用の見本を作る

1. VSCodeで `.env` を作り、`DEMO_API_KEY=local-example-only` と書きます。
2. `.env.example` を作り、`DEMO_API_KEY=replace-me` と書きます。
3. `.gitignore` を作り、`.env` と1行書きます。3ファイルを保存します。
4. `git status --short --ignored` で3ファイルの状態を確認します。

**完了チェック**

- [ ] `.env` は `!!`、`.env.example` と `.gitignore` は `??` と表示された。

## 応用演習

### 課題2：コミット予定の差分を確認する

1. `.env.example` と `.gitignore` だけをステージします。
2. `git diff --cached` で2ファイルの差分を読みます。
3. `.env` の中身が入っていないことを確かめてコミットします。コミット後に `git show --stat HEAD` で対象ファイルを確認します。

**完了チェック**

- [ ] コミットに `.env.example` と `.gitignore` の2つだけがあり、PCには `.env` も残っている。

## 発展演習

### 公開後の対応を考える

「チームのメンバーが、本物のAPIキーを含むファイルをGitHubにpushした。ファイルの内容を削除するPRは作成済みだが、キーはまだ使える」と仮定します。これは机上演習です。

1. 最初に誰が、どこで、何をするか決めます。
2. 担当者に伝える内容を、値を含めずに2〜3行で書きます。
3. ファイルの内容を削除するPRだけでは対応が終わらない理由を説明します。

**完了チェック**

- [ ] 発行元での失効、チームへの連絡、過去のコミットへの対応を説明できる。
