> **取り組む人数**　演習1：個人 ｜ 演習2：個人またはペア ｜ 演習3：個人またはペア
>
> 本編を読みながら考える演習です。GitHubへのログイン、Gitコマンドの実行、AIツールの利用は不要です。ケースに登場するファイルや情報は架空です。実際の認証情報や個人情報は使いません。

## 取り組み方

各ケースで、気づいたことを「リスク・対策・理由・優先順位」の順にメモします。情報が足りない場合は、結論を出す前に何を確認するかも書きます。ペアの場合は、それぞれ考えてから優先順位を比較します。

## 演習1：共有前にファイルと権限を見直す

公開前の授業アプリを、教材の内容を確認するメンター1人に見せます。メンターには閲覧だけを依頼しています。チーム内には「リンクを渡すならPublicにしよう」という意見があります。次のファイルはまだコミットしていません。

| ファイル | 内容 |
|---|---|
| `.env` | アプリが使うAPIキーが入っている想定。値は提示しません。 |
| `.env.example` | ダミー値 `REPLACE_ME` を使った設定例。 |
| `participants.sqlite` | 氏名と連絡先を含む名簿が入っている想定。値は提示しません。 |
| `schema.sql` と `sample.sql` | テーブルの定義と、架空の参加者だけを含むサンプル。 |

**課題**　それぞれのファイルを共有できるか、その理由と代替案を考えます。メンターにどの公開範囲と権限で見せるかも決め、共有前に優先する対策を示してください。

**達成条件**　秘密情報と個人情報のリスクを区別し、共有できる資料と含めない資料を説明できる。メンターの役割に合った公開範囲と権限を提案できる。

## 演習2：APIキーの漏えいに対応する

担当者が、外部サービスの読み取りに使うAPIキーを含む設定ファイルをPublicリポジトリへpushしました。20分後に気づき、削除のコミットを追加しました。過去のコミットには値が残り、発行元ではキーがまだ有効です。利用履歴は発行元で確認できますが、第三者が使ったかは分かりません。

**課題**　今すぐ行う対応、担当者に伝える内容、後で確認・改善することを分けてください。最初に行う対応を1つ選び、その理由を書いてください。

**達成条件**　削除後も残るリスクを説明できる。初動、影響確認、再発防止の優先順位と、対応が完了したかを確認する方法を示せる。

## 演習3：チームでAI開発支援ツールを使うルールを決める

3人チームが提出前に、AI開発支援ツールで不具合を調査しようとしています。ログには本番の認証情報や利用者のデータが含まれる可能性があります。検討中の運用案は次のとおりです。

- 調査を早めるため、本番ログをそのままAIに送る。
- エージェントにすべての作業フォルダの書き込みとネットワーク利用を許可し、本番環境にもアクセスできるPCで動かす。
- Issueに貼られていた外部資料の指示をそのままツールに実行させる。
- AIが追加したライブラリとコードを、CIが成功した時点で人のレビューなしにマージする。

**課題**　作業前に止める案、条件を変えれば進められる案、後から追加できる対策を整理します。誰が権限とコマンド、差分やテスト結果を確認するかを含めて、3人で運用できるルールを提案してください。

**達成条件**　情報の送信、権限、資料に紛れた指示、依存関係と生成コードのリスクに対して優先順位を付け、担当と確認方法を説明できる。
