## 演習1：GitHubに反映されるタイミング

**回答例**　`git add .` は現在のフォルダ以下の変更をステージします。GitHubに送るには、その変更を `git commit` で履歴に記録し、`git push` を実行します。 [出典：01 基本操作](../01-basic.md#1-6-add--commit--pushでgithubに反映する)

## 演習2：注文がない商品の検索

```sql
SELECT p.name
FROM products AS p
LEFT JOIN order_items AS oi ON oi.product_id = p.id
WHERE oi.id IS NULL;
```

| name |
| --- |
| ノート |

`LEFT JOIN` で注文明細がない商品も残し、`IS NULL` で対応する明細がない行を選びます。 [出典：SQL入門](../sql/README.md#4-よくあるミスnullを比較する)

## 演習3：教材で確認できない質問

**回答例**　この教材からは来年度の提出期限を確認できません。対象の授業名を確認し、授業の案内や学内ポータルを参照してください。

## 演習4：言い換えた質問を検索する

**キーワード例**　「ステージ」「取り消し」「restore」。[04章のトラブル対処](../04-troubleshooting.md)の4-5からステージ解除の説明を確認します。`git restore --staged ファイル名` はステージから外す操作で、作業ファイルの編集は残ります。

**確認質問の例**　「`git add` で選んだ状態だけを解除したいですか。それともファイルの編集内容も元に戻したいですか？」。質問の意図が分かるまで、編集を破棄するコマンドの実行は案内しません。

## 演習5：検索と回答を分けて評価する

| 質問 | 期待する回答 | 参照先 | 避けたい誤り |
| --- | --- | --- | --- |
| `git add .` でGitHubに反映？ | ステージ・コミット・pushの順を説明する。 | 01章の1-6 | addだけで送信したと答える。 |
| 注文がない商品をSQLで探す | `LEFT JOIN` と `IS NULL` を使い、ノートが出る。 | SQL入門の4節 | `= NULL` で検索する。 |
| 来年度の課題の提出期限 | 教材では確認できないと伝え、授業案内を案内する。 | 教材に根拠なし | 日付を推測する。 |
| 選んだ変更だけ外したい | ステージ解除の意味を確認し、適切な手順を案内する。 | 04章の4-5 | 編集内容まで消える操作を案内する。 |

各行に「正しい節が検索結果に出たか」と「回答・出典が期待どおりか」の2列を追加し、別々に記録します。提出期限の質問では「正しい節が出たか」を対象外とし、根拠不足を伝えられたかを確認します。

## 演習6：回答と出典をレビューする

**確認例**　「コミットすればGitHubに反映される」と書いた回答は、出典の送信手順を読み直し、コミットとpushを分けて説明します。すでに説明できている場合は、出典のどの記述で確認できたかを示します。

- **正しさ**　手順・コマンド・結果が、参照した教材に合っている。
- **出典**　開いた先の本文を読むと、回答の結論を確認できる。
- **情報が足りない場合の対応**　日付などを作らず、必要な情報や確認先を示している。
