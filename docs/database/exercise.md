# データベースの基礎と実践｜演習

[← 補足教材の目次](README.md) ｜ [回答例・解説](answer.md) ｜ [AIの使い方の共通方針](../../README.md#学習と開発でのaiの使い方)

各課題は、新しい練習用DBに既存の [`sample.sql`](../sql/sample.sql) を読み込んだ状態から始めます。基本・応用は[ブラウザ上のSQLite](../sql/README.md#準備ブラウザでsqliteを開く)でも実行できます。

## 基本演習：商品を取得・追加・更新する

**目安**　15〜20分。

1. 在庫が5個以下の商品名と在庫数を、在庫の少ない順に表示します。
2. IDが4、カテゴリが文具、価格が220円、在庫が5個の商品「付箋」を追加します。
3. 付箋の在庫だけを9個に更新します。

**達成条件**　在庫の少ない商品を2件取得できる。付箋を含む4商品があり、既存3商品の在庫は変わっていない。

## 応用演習：商品とタグを設計する

**目安**　20〜25分。

1商品に複数のタグを付けられ、同じタグを複数の商品に付けられるようにします。ペンには「学習用」と「定番」、ノートには「学習用」を付けます。マグカップにタグは付きません。

ER図に各表の主キー・外部キーを示し、DBに構造とタグのデータを追加してください。「学習用」のタグを持つ商品名を商品ID順に表示します。

**達成条件**　ノートとペンが1件ずつ表示される。商品とタグの同じ組み合わせを重複登録できない設計になっている。

## 発展演習：既存データを保って列を追加する

**目安**　25〜35分。

発注が必要になる在庫数を表す `reorder_level` 列を、既存の `products` に追加します。初期値は5で、0以上の整数を想定します。

SQLite CLIを使う場合は、`docs/database` をカレントディレクトリにして、未使用の練習用ファイル名を指定します。ターミナルで1行目を実行してSQLiteを起動し、残りは `sqlite>` に入力します。初期データを作り、未使用の名前で変更前のコピーを保存します。

```text
sqlite3 reorder-practice.db
.bail on
.read ../sql/sample.sql
.backup reorder-before.db
.quit
```

[変更ファイルの例](migrations/001-add-reorder-level.sql)を読み、最初のエラーで停止する設定で練習用DBに適用します。CLIでの適用方法は[回答例の発展演習](answer.md#発展演習既存データを保って列を追加する)を参照できます。作業前後のデータと適用履歴を比較し、チームへ伝えるPR説明を作ってください。実際のPR作成は不要です。練習用DBとバックアップはGitに追加せず、やり直す場合は両方に未使用のファイル名を使います。

**達成条件**　発注点が5の既存商品が3件あり、元の商品ID・在庫・注文明細の内容は同じ。適用履歴に変更が1件あり、PR説明に確認結果と失敗時の対応が書かれている。
