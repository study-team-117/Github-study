[練習用データ](sample.sql)を読み込んだSQLiteで、次のSQLを書いてみましょう。

1. 在庫が5個以下の商品名と在庫数を、在庫の少ない順に表示する。
2. カテゴリごとの在庫数の合計を表示する。ヒントは `SUM` と `GROUP BY`。
3. 注文明細のID、商品名、注文数量を明細IDの順に表示する。ヒントは `order_items.product_id` と `products.id` を `JOIN` で結び付けること。

## 発展課題：在庫表示と注文一覧

4. `CASE` で在庫が5個以下の商品に「少ない」、それ以外に「十分」と表示する列 `stock_status` を作る。商品名・在庫数・在庫状況を商品ID順に表示する。
5. 課題3の結合を `order_item_summary` というビューにする。`CREATE TEMP VIEW … AS SELECT …` で定義し、そのビューから明細ID順に表示する。

## 追加演習：条件指定からデータ変更まで

6. 文具のうち価格が150〜300円の商品の名前と価格を、価格が安い順に表示する。範囲の両端も含める。
7. 価格が高い順に並べ、2番目の商品だけを表示する。ヒントは `LIMIT` と `OFFSET`。
8. カテゴリごとに在庫数を合計し、合計が10個以上のカテゴリだけを表示する。ヒントは `HAVING`。
9. すべての商品について、商品名と明細の注文数量を商品ID順・明細ID順に表示する。注文明細がない商品も残し、その行の注文数量は `NULL` とする。
10. 商品全体の平均価格より高い商品の名前と価格を、価格順に表示する。ヒントは副問い合わせと `AVG`。
11. `BEGIN` で練習を始め、「付箋」（IDは4、カテゴリは文具、価格は220円、在庫は5個）を追加する。在庫を9個に更新したら、その商品だけを削除する。各操作の直後にIDが4の行を検索し、最後に `ROLLBACK` で終了する。最後に商品数が元の3件であることを確認する。

## チャレンジ課題

12. 商品ごとの注文数量を合計し、現在の在庫数と見比べる一覧を作る。明細がない商品も表示し、注文数量の合計は0とする。「注文数量の合計 − 在庫数」が正なら、その数を不足数とし、それ以外は0とする。商品名・在庫数・注文数量の合計・不足数を、不足数の多い順、同じ場合は商品ID順に表示する。ヒントは `LEFT JOIN`、`SUM`、`COALESCE`、`CASE`。
13. **同じカテゴリの平均価格以上**の商品だけを一覧にする。カテゴリ・商品名・価格・カテゴリの平均価格を表示する。平均はカテゴリ内の全商品で計算し、表示はカテゴリ名の昇順、同じカテゴリ内では価格が高い順、同じ価格なら商品ID順とする。ヒントは `WITH` でカテゴリ別の平均を作り、商品テーブルに `JOIN` すること。
