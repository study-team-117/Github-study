本文のタスク一覧CLIを題材に、AIへの依頼、担当間の引き継ぎ、レビューを練習します。教材に載せた情報だけで解けます。回答はメモにまとめ、実際の認証情報や個人情報を使わないでください。想定時間は3問で約30分です。

## 基本演習　曖昧な指示を具体化する（8分）

別の担当者がAIに「タスク一覧を使いやすくして」とだけ依頼しようとしています。利用者は完了済みタスクだけを一覧表示する機能が欲しいと話しています。普段の一覧、保存データの形式、既存の依存関係は維持したいそうです。

[03節の比較表](README.md#03-aiへの指示の出し方)を参考に、実装前の調査から始められる依頼文に書き換えてください。

**達成条件**　利用者の目的、編集してよい範囲、維持する挙動、機能を確認できる受入条件、計画を確認するタイミングが読み取れる。

## 応用演習　レビュー担当に引き継ぐ（10分）

実装担当から、次のメモを受け取りました。実装担当との会話はレビュー担当から見られません。

> 予定どおり絞り込みを追加した。ブランチは `feature/tasks-done`、コミットIDは `a1b2c3d`（架空）、比較先は `main`。変更は `tasks.py`。手元の2件のデータで、引数なしの全件表示と `--done` の完了済み1件表示を確認した。完了済みが0件の場合は未確認。

要件を知らないレビュー担当にも渡せるように、この記録と[本文の実践例](README.md#07-実践例)からMarkdownの引き継ぎメモを作ってください。

**達成条件**　レビュー対象、期待する動作、確認済みと未確認の区別、レビュー担当に見てほしい点が分かる。

## 発展演習　AIのレビュー結果を検証する（12分）

要件は本文と同じです。AIが次の差分を作成し、別のAIが「`--done` を付けたら完了済み1件だけが表示された。テストが通ったのでマージしてよい」とレビューしました。

```diff
 parser = argparse.ArgumentParser()
+parser.add_argument("--done", action="store_true")
 args = parser.parse_args()

 for name, done in tasks:
-    print(name)
+    if done:
+        print(name)
```

1. どの要件への違反が差分から読み取れるか、該当箇所とともに指摘してください。
2. レビューの主張から判断できる範囲を整理し、マージ前に確かめる入力と期待結果を書いてください。

**達成条件**　指摘に根拠があり、指定時・未指定時・完了済みが0件の場合について、確認方法と期待結果が説明できる。
