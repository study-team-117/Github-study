回答例を参考に、依頼や判断の理由が次の担当にも伝わるかを確認してください。

## 基本演習　曖昧な指示を具体化する

> 利用者が完了済みタスクだけを確認できるようにしたいです。先に既存の引数処理と一覧表示を調べ、変更する箇所とテスト案を提示してください。計画を確認した後、`tasks.py` と対応するテストだけを変更してください。外部依存関係とデータ形式は現状のままにします。`--done` 指定時は完了済みだけ、未指定時は全件を従来と同じ順番で表示します。完了済みが0件なら、`--done` 指定時は何も表示せず正常終了します。

**評価の観点**　目的と対象ファイルから作業範囲が分かるか。受入条件を実行結果で確かめられるか。計画確認前の作業が調査に限られているか。

## 応用演習　レビュー担当に引き継ぐ

```markdown
- 目的: タスク一覧で完了済みだけを確認できるようにする。
- 受入条件: --done で完了済みだけ、引数なしで全件を従来と同じ順番で表示する。
  完了済みが0件なら --done 指定時は表示なしで正常終了する。
- 対象: feature/tasks-done の a1b2c3d（架空）。比較先は main。変更は tasks.py。
- 確認済み: 2件のデータで、引数なしの全件表示と --done の1件表示を手動確認。
- 未確認: 完了済みが0件のときの出力と終了状態。
- 依頼: 既存動作への影響と未確認のケースを確認し、該当箇所と再現条件を添えて指摘する。
```

**評価の観点**　受け手が同じ差分を特定できるか。報告にないテスト結果を推測で補っていないか。次に確認する内容が具体的か。

## 発展演習　AIのレビュー結果を検証する

`if done:` は引数の値に関係なく、完了済みのタスクだけを表示します。既定の全件表示が失われるため、修正が必要です。レビューの報告は `--done` 指定時の通常ケースだけを確認しています。

| 確認する条件 | 期待結果 |
|---|---|
| 完了済みと未完了が各1件、引数なし | 両方が従来と同じ順番で表示される |
| 同じデータで `--done` | 完了済みの1件だけが表示される |
| 全件が未完了で `--done` | 何も表示せず正常終了する |

修正後に3つの条件を再確認し、対象コミットと結果をPRに残します。

**評価の観点**　レビューコメントの結論と、その根拠で確かめられた範囲を区別しているか。見つけた問題を差分と期待結果で説明できるか。修正後の確認が元の不具合と受入条件をカバーしているか。
